# 前端视觉与慢网体验优化（2026-10-23）

目标：**更耐看的界面 + 更顺的过渡 + 弱网下更快"有画面"**。不改信息架构、不改接口契约。

## 1. 设计 token（先建立语言，再改组件）

`tailwind.config.js` + `index.css` 里新增：

| token | 值 | 用途 |
|---|---|---|
| `ease-out-quint` | `cubic-bezier(0.22,1,0.36,1)` | 位移/透明度（起步快、收尾稳，最"跟手"） |
| `ease-spring` | `cubic-bezier(0.34,1.42,0.64,1)` | 弹层/徽标（轻微过冲，有物理感） |
| `shadow-soft / lift / panel` | CSS 变量，浅深各一套 | 静置 / 悬停 / 浮层三级高度 |
| `--app-bg` | 浅 `#e9edf3` / 深 `#161923` | 页面底色，刻意比卡片深一档 |
| `--card-border` | 浅 `rgb(15 23 42/.09)` / 深 `rgb(255 255 255/.07)` | 统一描边，替代各处手写的 ring |
| `--ambient-1/2` | 品牌橙 + 冷蓝 | 页面顶部/左下的环境光 |

之前缓动字面量散落在各组件（`ease-out`、`cubic-bezier(0.16,1,0.3,1)`、`0.22,1,0.36,1`…），
同一个 App 里出现三套节奏；统一 token 后整体节奏才一致。

## 2. 视觉质感

- **底色分层**：浅色主题最容易踩「白底 + 白卡片」的坑，层次全靠阴影硬撑。底色压深一档后
  卡片、侧栏、弹层自然分层；深色下则靠 `--card-border` 的白 7% 勾出边缘。
- **卡片材质**：`.card` = 圆角 2xl + 1px 主题描边 + 顶部 1px 内高光 + 柔和外阴影。
- **主按钮**：竖向渐变（橙 400→600）+ 内高光 + hover 提亮 + 按下微缩，接近实体按键。
- **封面**：统一 `.media-frame` 细边 + hover 抬升 + 阴影加深 + 图片 1.04 微缩放；
  进度条改成带光晕的渐变胶囊。
- **玻璃层**：桌面侧栏 `bg-ink-900/55 + blur-xl`；移动底栏改用 `/92 + blur-md`
  （手机上背景模糊是每帧重采样，通透度换掉帧不划算）。
- **导航激活态**：品牌色薄底 + 左侧指示条（缩放进出）+ 图标 drop-shadow，三重信号。
- **环境光**：`body::before` 两层固定径向渐变（fixed + 独立合成层，不影响滚动）。
- **详情页顶部光晕**：拿封面自己当光源（同 URL 命中缓存），`blur(40px)` + 径向 mask 柔化。
  宽屏下详情页右侧原本一大片死白，现在被底色/光晕填住。
- **阅读器弹层强制深色**：阅读器是纯黑沉浸层，浅色主题下弹出白面板会像"另一个 App"。
  给章节抽屉与设置面板套一层 `.dark`，只影响这两个弹层。
- **输入框统一**：Login/Settings 里手写的边框输入框收归 `.input`（圆角、focus ring 一致）。

## 3. 过渡动画

- **路由切换**：`.anim-route`（淡入 + 上浮 8px，260ms，out-quint）。比原来的纯淡入更有方向感。
- **列表错峰**：网格前 12 张卡片按 26ms 递增入场，首屏是"依次浮现"而不是整片同时闪出。
- **弹层**：底部 Sheet 320ms out-quint + 顶部把手；确认框用 spring 过冲。
- **按压反馈**：`.btn` / `.press` 用 `active:scale-[0.97]` + 更短的 150ms 过渡，点哪儿都有回应。
- **性能取舍**：删掉 `.anim-card-in` 的 `will-change: transform, opacity` ——
  网格里 100+ 张卡片各留一个合成层会吃显存，而 340ms 的一次性动画浏览器本来会自动提升。
- **无障碍**：`prefers-reduced-motion` 下同时清零 `animation-delay`，否则错峰卡片会在
  不可见状态干等 300ms 才出现。

## 4. 慢网（弱网）优化

最关键的一条：**首屏不再白屏**。

`index.html` 里内联了两段东西（合计约 2.5KB，零额外请求）：

1. **首帧主题脚本**：同步读 `fakenews-theme`，在主 CSS/JS 到达前就定下背景色与 `color-scheme`，
   避免"先白闪一下再变深色"。
2. **启动壳**：与首页同构的骨架（品牌名 + 搜索框 + 横滑卡 + 网格），纯 CSS 绘制。
   React 挂载时整体替换 `#root`，无需手动清理。

配套改动：

- 详情页加载态从"居中 spinner"换成**同构骨架屏**（封面块 + 标题行 + 按钮行 + 章节行），
  数据到达时不重排。
- 阅读器加载态换成**页面比例骨架** + 强制深色，并保留"取消并返回详情"出口。
- 首屏前 6 张封面 + 4 张"继续阅读"封面给 `loading=eager` + `fetchpriority=high`，
  其余保持懒加载：弱网下先出可见区域，而不是按 DOM 顺序排队。

### 实测（Edge headless，400kbps / RTT 300ms / 冷缓存，首页）

| 指标 | 优化前 | 优化后 |
|---|---|---|
| 首次绘制（启动壳可见） | 3216 ms | **1000 ms** |
| 真实卡片出现 | ~4300 ms | ~4280 ms |

> 说明：FCP 之前只有"深色空白"，因为 `#root` 是空的、CSS 才刚到；现在 HTML 解析完就有骨架。
> React/JS（118KB gz，3.1s）与接口往返没动，所以"数据到齐"时间不变——
> 弱网下能省的主要是**感知等待**，不是字节数。

## 5. 高亮颜色（accent）

设置 →「主题」区块里的「高亮颜色」可选 **琥珀橙（默认）/ 空色 / 豆沙绿**。

| 选项 | 色值 | 说明 |
|---|---|---|
| 琥珀橙 `amber` | `#f97316` 系，未改参数 | 原「暖橙」，仅改名 |
| 空色 `sora` | 标准色 `#A0D8EF`（RGB 160 216 239，HSL 197° 71% 78%） | 日本传统色「そらいろ」，白字只有 1.55:1，标准色落 200 档当浅底强调；主色顺 H≈197° 压到 500（白字 4.5:1）/ 600（6.8:1）才压得住白字 |
| 豆沙绿 `bean` | 标准色 `#C7EDCC`（RGB 199 237 204） | 是护眼底色、极浅，只能占 200 档；主色顺 H≈128° 压到 500/600 才压得住白字 |

品牌色从写死 hex 改成 CSS 变量重映射，这是关键一步：

| 层 | 位置 | 作用 |
|---|---|---|
| Tailwind | `brand-50..900` → `rgb(var(--brand-*))` | 几十处 `bg-brand-500` / `text-brand-400` 一行不用改 |
| 默认值 | `index.css` 的 `:root` | 琥珀橙 |
| 覆盖 | `:root[data-accent='sora' \| 'bean']` | 空色 / 豆沙绿 |
| 实心渐变 | `--brand-grad-from/to` | 各色相「压白字还看得清」的区间不同，所以两端单独给 |
| 深色微调 | `:root.dark[data-accent='sora' \| 'bean']` | 各提亮一档：空色不加亮「发不出来」，豆沙绿太深会显脏 |

四个要知道的点：

1. **应用位置在「守卫内、路由外」**（`components/layout/ThemeSync.tsx`），不在 `AppShell`。
   阅读器是脱离 AppShell 的全屏路由，放 AppShell 会漏掉它（章节抽屉、进度条都吃 `brand-*`）。
2. **localStorage 镜像 + `index.html` 首帧脚本**：`fakenews-accent` 在首帧就写成 `data-accent`，
   否则慢网下会先看到橙骨架、JS 到了再变色。
3. **旧键迁移**：`theme.ts` 的 `normalizeAccent` 把 `orange → amber`、`blue/prussian → sora`、
   `gray → bean` 统一归一化，设置查询与 `index.html` 首帧脚本都走同一套映射。
   「灰换豆沙绿、蓝换普鲁士蓝」是第一轮、「普鲁士蓝换空色」是第二轮，都靠这层完成迁移，
   用户升级后不需要重新选一次。
4. **启动壳的 logo 占位保持品牌橙**：它就是真 logo（`logo.png` 位图）的替身，
   跟着高亮色变反而会在 React 挂载那一刻闪一次色。

环境光 `--ambient-1` 也改成 `var(--brand-500) / 0.16`，整页顶部的薄雾会跟着高亮色走。

## 6. 打开页面时的「轻微错位」

症状：点首页 / 书架 / 搜索 / 漫画库，页面打开瞬间内容像错开一下再对齐。
用 `PerformanceObserver` 采 `layout-shift` + 逐帧打 `main` 几何，定位到三个叠加的原因：

| 原因 | 实测证据 | 修法 |
|---|---|---|
| 切页不重置滚动位置 | 首页滚到 y=69 再点「书架」，新页更矮，`scrollY` 被 clamp 到 4；帧序列 `top` 是 -69 → -13 → -4 | `ScrollManager`：PUSH 回顶、POP 恢复离开时的位置 |
| 滚动条出现/消失 | 内容区宽度在 1432↔1440 之间跳 8px（`main` 宽度 1208→1216） | `html { overflow-y: scroll }`；`scrollbar-gutter: stable` 在当前 Chromium 根元素上不预留，只能兜底 |
| 「继续阅读」数据到齐才插入 | 把筛选区整体推下 267px，CLS=0.0243 | 同尺寸骨架占位，CLS → 0 |
| 路由入场动画带 8px 位移 | `main.top` 8 → 5 → 2 → 0 | `.anim-route` 改纯淡入；位移留给卡片级 `.anim-card-in` |

阅读器要全屏沉浸，用 `html:has(body.reader-lock) { overflow-y: hidden }` 让出滚动条槽
（实测 `clientWidth === innerWidth`）。

## 7. 详情页不再被封面「带跑」

症状：同一套详情页，换一本书打开就变个样——版面高低不一、顶部底色也跟着变。

用 `tools/detail_shot.mjs` 逐本量同一页的几何，两个独立原因：

| 原因 | 实测证据（1440 宽，浅色） | 修法 |
|---|---|---|
| 封面框只给了宽、没给高，图片高度由自身像素比例决定 | 方形封面 192×145、3:4 封面 192×271、竖长封面 192×418；章节区顶部随之 245→518（漂 273px） | 封面框固定 `aspect-[3/4]` + `h-full object-cover`（与网格卡片、骨架屏同比例），实测 8 本全部 192×256、章节区顶部统一 356 |
| 顶部光晕拿封面图模糊 40px 当光源 | 蓝封面的详情页整个顶部发蓝，深色封面把顶部压成灰黑，标题对比度跟着浮动 | 改成 `.page-ambient`：只用 `--brand-*` 派生两层径向渐变（琥珀橙 / 空色 / 豆沙绿各一个稳定氛围），透明度由 `--page-glow-a/b` 控 |

顺带：封面加载失败时光晕依然在，页面不会塌成一块纯底色。

```bash
node tools/detail_shot.mjs --tag=light --theme=light          # 逐本打印封面尺寸/章节区顶部并出图
node tools/detail_shot.mjs --theme=dark --accent=bean --ids=<id>   # 指定高亮色/单本核对
```

## 8. 四格章节的「已读」怎么表达

四格模式里原来用角上一个 9px 的 `✓` 标已读。实测它在 44px 的格子里实渲不到 4px 高、
`brand-400/70` 又淡，基本看不见；而且语义是反的——读到一半有底部的进度线，读完了反而只剩个字符。

试过三种，只有第三种可用：

| 方案 | 问题 |
|---|---|
| 右上折角（dog-ear） | 单看好，读得多的时变成一排橙色三角，和「当前章」的实心品牌色抢注意力 |
| 底部进度线封满 | 12 格里有 9 条整宽的橙线，比小勾更吵 |
| **把格子抽空**（采用） | 已读=透明底 + 一圈卡片描边 + 章号降一档；未读=实心块；当前章=实心品牌色 |

抽空之后信息层级正好对：视线落在**还没读**的实心块上，已读的退成一层很轻的底纹，
读得越多整片越轻。要点：

- 描边复用 `var(--card-border)`（浅色 9% 黑 / 深色 7% 白），保住格子结构又不抢戏
- 章号浅色用 `ink-500`（4.4:1），深色提一档到 `ink-400`（`ink-500` 在深底上只有 3.6:1，太暗）
- `:hover` 把底色补回一半，说明抽空的格子仍然是按钮
- 详情页章节区和阅读器章节抽屉共用 `.chapter-done`，两处观感一致
- 顺带给格子补了 `title`：已读显示「· 已读完」，鼠标停留也能读到状态

## 9. 「重置进度」确认后页面没变化（缓存 key 前缀写错）

现象：详情页点「重置进度」→ 确认 → 弹窗关掉了，但按钮还是「继续阅读（33%）」、
章节格子的已读标记也还在。刷新页面才变。

关键证据（`tools/reset_progress_check.mjs`）：重置后 `GET /api/progress?comicIds=...` 已经是空数组，
**但整个过程中 `GET /api/comics/{id}` 一次请求都没发**。也就是说服务端早就删干净了，
前端连问都没再问一次。

根因是 react-query 的缓存 key 前缀：

```ts
// 列表：['comics', query]
// 详情：['comic', id]     ← 单数，和上面不同前缀
qc.invalidateQueries({ queryKey: ['comics'] });   // 只命中列表，详情纹丝不动
```

`invalidateQueries` 有 `exact: false` 只是「按 key 前缀匹配」，不是「按名字相似匹配」。
`'comics' !== 'comic'`，所以详情那条查询根本没被标记为 stale；再加上
`useComicDetail` 的 `staleTime: 30_000`，页面会一直拿着旧数据渲染。

修法：把重置收到 `useResetProgress()` 里，跟 `usePutProgress` 对称地失效三处
（详情 / 列表 / 历史），页面不再手写 invalidate。同时：

- `ConfirmDialog` 接上已有的 `busy` / `error`：请求中禁用按钮并显示「重置中…」，
  失败**保持弹窗打开并显示原因**（原来 `.finally` 直接关窗，失败等于「点了没反应」）
- `danger` 标红，重置是不可逆操作
- 顺手扫出两处同源问题：详情页「重扫」和书架「删除单条阅读记录」也只失效了列表 key，
  一并补上详情 key

验收：

```
重置前: {"doneCells":2,"totalCells":12,"startBtn":"继续阅读（33%）","resetBtnVisible":true}
重置后: {"doneCells":0,"totalCells":12,"startBtn":"开始阅读","resetBtnVisible":false}
重置后详情接口请求次数: 1 /api/comics/8a47483571299bde
服务端 progress: []
PASS
```

## 10. 平移模式拖到首/末页的反馈

**改造前**：轨道先 `setPos(0|2)` 把整页滑出去（那一侧槽位是空的，露出的是黑底），等 260ms 后发现
换不了章再滑回来；同时整页横抖 20px，屏幕正中弹一个纯黑不透明胶囊。三个问题叠在一起：
先闪一下黑、再抖一下、最后盖一个像系统 alert 的黑块。

**改造后**，拖动和松手分成两段，各自说一件事：

| 阶段 | 表现 | 实现 |
|---|---|---|
| 拖动中 | 页面仍按 0.3 阻尼跟手，被拉开的那一侧出现品牌色柔光，亮度 = 实际拉开比例 | `.pan-edge-glow`（绝对定位、`pointer-events:none`），`--pull` 由 `usePanTrack` **直接写 DOM**，不经 React 渲染 |
| 松手（到头） | 光带收光 + 轨道用 380ms 带过冲的曲线回位 + 页面「顶住-回弹」一次 + 玻璃提示卡从拉动那侧浮入 | `PAN_SETTLE`（back-out）对 `PAN_EASE`；`anim-edge-bump-*`；`.reader-notice` |

要点：

- **不再滑出去露黑**。判定条件是「这一侧既没有相邻页，也没有相邻章」（`target < 0 && !canGo`）——
  同一段代码里「章末还有下一章」仍然走原来的滑出换章，两条路径彻底分开。
- **轻碰不提示**。越界位移必须达到 `EDGE_TELL_RATIO`（30% 的满量，约等于手指拖过 19% 页宽）才调
  `onEdge`，否则只回弹、不弹卡片。反复顶边不会一直糊提示。
- **光带跟手但零渲染**。拖动中每帧都变的值走 `el.style.setProperty('--pull', …)`，
  React 只负责这一次 `setPos`；松手写 0，靠 CSS `transition: opacity` 自然收光。
- 光带是「贴边的竖直渐变」而不是居中 radial 光团：边缘最亮（`brand-200` 0.85）、34% 处退到 0.34、
  再乘一层横向 mask 到 82% 归零。试过 radial 和 `mix-blend-mode: screen`，前者在纯黑底上像一团雾、
  后者会把暗部发灰成褐，都弃用。
- 提示卡 `.reader-notice`：半透明玻璃 + `blur(16px) saturate(160%)` + 顶部内高光，
  到头类再掺一点品牌色描边（`.reader-notice-edge`），并从拉动那一侧 `translateX(±14px)` 浮入；
  换章提示（进入/回到某章）共用同一套胶囊，只是没有图标、方向偏移为 0。
- 回弹幅度从 20px 减到 9px 并加入 3px 过冲与 `scale(0.997)`：读起来是「顶到纸边」，
  而不是「画面晃了一下」。

验收（`tools/edge_pull_check.mjs`，真实 mouse 事件驱动，逐帧采样）：

```
✓ 拖动中左侧柔光亮起 — 采样 77 帧带左侧光，最大 opacity=0.65
✓ 柔光亮度随拉开量上升 — --pull 峰值 0.69
✓ 越界位移被阻尼限制在窄缝 — pos 最小 0.886（1 为居中，被拉开最多 0.165 页宽）
✓ 松手后出现到头提示 — 已经是第一页了
✓ 提示带方向图标 / 页面跑了一次回弹动画 — bump 方向 prev / 轨道回中 / 柔光收光
✓ 轻碰不打扰（无提示）
✓ 提示文案为「最后一页」/ 页面回弹方向为 next
✓ 有下一章时走换章（不误报到头） — 提示=进入「第2章」
```

## 12. 多端适配（手机 / 平板横竖屏 / 笔记本 / 桌面 / 2K）

### 12.1 版式基线（先立口径，再谈改）

| 宽度 | 导航 | 封面列数 `.comic-grid` |
|---|---|---|
| < 640（手机竖） | 底部 Tab（含安全区 `pb-[env(safe-area-inset-bottom)]`） | 3 / 4（≥640） |
| 640–1023（平板竖、手机横） | 图标 Rail（`sm:flex lg:hidden`） | 4 / 5（≥768） |
| ≥ 1024（平板横、笔记本、桌面） | 侧栏（图标 + 文字） | 6 / 8（≥1280） |

⚠️ 根容器是 `sm:flex` 而不是 `lg:flex`：Rail 在 640–1023 区间可见，若根容器仍是 block，
Rail 的 `sticky h-dvh` 会在文档流里占满一屏，把主区整个顶出首屏（平板竖屏只看到一排图标，踩过）。

### 12.2 探针 `tools/responsive_check.mjs`

12 个视口（320×568 / 360×740 / 390×844 / 844×390 / 744×1133 / 820×1180 / 1133×744 / 1024×768 /
1366×1024 / 1440×900 / 1920×1080 / 2560×1440）× 7 个页面（首页/书架/搜索/漫画库/设置/详情/阅读器），
每页量 6 项：

1. **横向溢出**：`scrollWidth - clientWidth` + 具体越界元素。祖先有 `overflow-x: hidden/auto/scroll`
   的一律豁免——阅读器三槽位平移轨道（`pan-surface` + `translate3d`）的邻页本来就在视口外，不算 bug。
2. **触控热区**：视觉尺寸与 `::after` 扩展区取较大者当作真实可按面积。手机/平板一律显式模拟
   `pointer: coarse`（`Emulation.setEmulatedMedia` + `setTouchEmulationEnabled`），否则 headless 下
   `mobile:true` 并不等于粗指针，触屏专用样式根本不会生效——这条一开始漏了，导致加码"看起来没效果"。
   阈值：触屏 40px（HIG 44 的下限）、鼠标 24px。
3. **命中归属**：每个控件中心处 `elementFromPoint` 必须落在自己身上。这是给热区加码兜底的——
   `.touch-hit::after` 是绝对定位会盖在上述兄弟之上，理论上可能抢走邻居的点击，必须逐个验证。
   例外：被 fixed 底栏遮住的不算（内容本来就会从 Tab 下面滑过去）。
4. **封面列数与卡片宽度**。
5. **导航形态**是否与宽度匹配。
6. **阅读器画幅**：按 `object-fit: contain` 与图片原始比例反算真实作画区域是否完整落在视口内
   （只看 img 元素的盒子会被误导——容器是撑满的）。

### 12.3 实测结果

| 项 | 结果 |
|---|---|
| 横向溢出 | 12 视口 × 7 页面 **全部 0** |
| 封面列数 | 3 → 4 → 5 → 6 → 8，断点全部按预期递进（91 / 104 / 114 / 151 / 135 / 145px） |
| 导航形态 | 手机底栏（@ y=510/682/786）、640–1023 Rail、≥1024 侧栏，均无偏差 |
| 阅读器画幅 | 全部 `contain` 且完整在屏（275×390 … 1016×1440） |
| 触控热区（修复前） | 手机/平板 **36 项不达标**：设置页分段选项 24px、开关 24×44、页码滑块 16px、首页排序按钮 **17px** |
| 触控热区（修复后） | **0 项**；手机 .chip 34px、按钮/输入框 44px，桌面维持 28/36px 不变 |

### 12.4 修复手法：只在触屏生效，桌面观感一字不动

```css
@media (pointer: coarse) {
  .chip { min-height: 34px; @apply px-4; }
  .btn, .input { min-height: 44px; }          /* 36 → 44 */
  .touch-hit { position: relative; }
  .touch-hit::after {                          /* 视觉不变，命中区补到 44×44 */
    content: ''; position: absolute;
    left: 50%; top: 50%; transform: translate(-50%, -50%);
    width: max(100%, 44px); height: max(100%, 44px);
  }
}
```

- 为什么不用 padding 撑：会连带改变桌面端间距与整行高度。想在桌面也加宽，就得接受一排按钮变胖。
- 为什么 `width: max(100%, 44px)` 而不是固定 44：控件宽度 ≥ 44 时原样展开，不会横向压到邻居。
  相邻色板中心间距 42px 时两侧各展开 22px，只会有 2px 重叠，而邻居中心（42px 外）不会被吃掉——
  这点由上面的「命中归属」逐项验证。
- `input[type=range]` 是替换元素，`::after` 不生效，得套一层 `<span class="touch-hit">`；
  探针判断热区时也要往 `closest('.touch-hit')` 上找，否则会误判成 16px 不达标。

### 12.5 窄屏设置行：让控件换行，而不是把标签挤成两三个字

320px 下「默认翻页模式」的四选项占 180px，标签被压到 66px 宽、折成「默认翻页 / 模式」两行。
改为 `flex-wrap` + 标签 `min-w-[8rem]`：够宽时完全维持原样（390px 起只有 3 行会换行），
不够宽时控件整块掉到第二行，标签永远是一行完整文案。
