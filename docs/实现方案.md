## 1. 产品定位与功能范围

### 1.1 定位

- **形态**：fnOS 桌面入口 → 响应式 Web 应用（手机 / 平板 / PC 浏览器），单容器部署
- **核心链路**：扫描 NAS 漫画目录 → 建索引 → 封面网格浏览 → 详情 → 全屏阅读器（进度记忆）
- **数据主权**：元数据、阅读进度、收藏、设置全部落在 NAS 本地（SQLite），无外网依赖

### 1.2 能力清单

| 能力 | 方案 | 说明 |
| --- | --- | --- |
| 首页结构 | 搜索区 → 继续阅读 → 漫画库筛选 → 展示区 | 见 P1 |
| 阅读记录 | 真正翻过页才计入「继续阅读」 | 只看封面/详情不记录 |
| 翻页模式 | 单页 / 双页 / 拆分双页 / 卷轴 | 拆分双页面向日漫跨页图 |
| 画质 | 标准压缩 / 原图切换 | 服务端缩略图 vs 原图流 |
| 翻页细节 | 翻页方向、动画、亮度、缩放、音量键翻页 | 音量键翻页仅移动端 |
| 封面 | 自动刮削 + 阅读中长按设封面 | 内置图识别 + 自定义上传 |
| 元数据 | 文件名/目录识别，可编辑名称/作者/简介 | 见数据模型 Comic.meta |
| 多库管理 | 多漫画库，章节/单篇两种类型，扫描/编辑/删除/排序 | Library 实体 |
| 章节管理 | 章节可编辑/删除 | 详情页章节抽屉管理 |
| 收藏 / 最近 | 收藏网格 + 阅读记录时间线 | 书架页承载 |
| 格式 | 可读：cbz/zip/rar/cbr/tar/cbt/pdf/epub + 散图目录；`7z`/`cb7`/`mobi` 仅入库不解析 | source 抽象保证扩展成本 O(1) |
| 权限共享 | 二期（fnOS 应用级单用户先行） | 见 §13 里程碑 |

## 3. 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 前端框架 | React 18 + TypeScript + Vite | 生态成熟，阅读器这类重交互组件生态最全 |
| 路由 | React Router v6 | 阅读器独立 fullscreen layout 诉求简单直接 |
| 服务端状态 | TanStack Query v5 | 列表/详情/进度缓存、失效策略、乐观更新开箱即用 |
| 客户端状态 | Zustand | 轻量；阅读器瞬态 + 偏好持久化（persist 中间件） |
| 样式 | Tailwind CSS + CSS 变量主题 | 响应式断点 + 暗色模式成本低 |
| 虚拟列表 | @tanstack/react-virtual | 章节列表 1000+ 项、webtoon 长滚动 |
| 手势 | 自研 Pointer Events 层 | 单击/双击/滑动/双指缩放统一处理，避免库体积 |
| 后端 | Go 1.26 + stdlib `net/http` | 单静态二进制、无 CGO、可交叉编译；`FROM scratch` 镜像 |
| 数据库 | `modernc.org/sqlite`（纯 Go） | 与二进制同编译，无原生依赖；WAL + 语句缓存 |
| 图像 | `golang.org/x/image`（CatmullRom → JPEG） | 零原生依赖；前端按 Content-Type 消费 |
| 压缩包 | `archive/zip`（zip/cbz/epub）+ `rardecode`（rar/cbr） | 纯 Go，流式读取 |
| PDF | WASM PDFium（`go-pdfium` + wazero） | 纯 Go 运行时内嵌 WASM，无需 CGO / 原生库 |

**部署形态**：单容器（`FROM scratch`，只含静态二进制 + 前端 dist），同一进程伺服 `/api/*` 与前端静态产物；漫画目录以卷挂载。不搞前后端双容器——NAS 上多一个容器多一分运维成本，收益为零。

## 5. 数据模型

### 5.1 前端契约类型（`app/web/src/types/`）

```ts
// ---------- 枚举 ----------
type ComicFormat  = 'cbz' | 'cbr' | 'zip' | 'folder' | 'pdf';
type LibraryType  = 'chapter' | 'single';          // 章节漫画 / 单篇漫画
type ReaderMode   = 'webtoon' | 'single' | 'double' | 'split';
type ReadDir      = 'ltr' | 'rtl';                 // 左翻(欧漫) / 右翻(日漫)
type FitMode      = 'width' | 'height' | 'contain' | 'original';
type Quality      = 'standard' | 'original';
type ReadStatus   = 'unread' | 'reading' | 'finished';

// ---------- 漫画库 ----------
interface Library {
  id: string;
  name: string;
  type: LibraryType;
  paths: string[];          // 关联的 NAS 目录（可多个）
  sort: number;             // 拖拽排序
  createdAt: number;
}

// ---------- 漫画 ----------
interface Comic {
  id: string;               // 路径 hash（稳定，重扫不变）
  libraryId: string;
  title: string;            // 展示名（命名解析产出，可被用户编辑覆盖）
  rawTitle: string;         // 文件名原始标题
  author?: string;
  description?: string;
  format: ComicFormat;
  path: string;             // NAS 绝对路径
  coverPath?: string;       // 自定义封面（用户上传/长按设定）
  sizeBytes: number;
  chapterCount: number;
  pageCount: number;        //  folder 型需索引后回填
  tags: string[];           // 派生：格式/库名/年份，供筛选
  fileModifiedAt: number;
  addedAt: number;          // 索引进库时间
  // —— 列表接口聚合下发的阅读态（避免前端 N+1 请求）——
  progress?: ReadingProgress;
  isFavorite?: boolean;
  lastReadAt?: number;
  readStatus: ReadStatus;
}

// ---------- 章节 ----------
interface Chapter {
  id: string;               // `${comicId}#${index}`
  index: number;            // 自然排序后的序号
  title: string;            // "第 01 卷" / 原名
  pageCount: number;        // folder 数图片 / 压缩包读中央目录，不解压
  sizeBytes: number;
  // 不含 comicId（外层详情已有）、也不含已读状态（分章进度已移除）
}

// ---------- 阅读进度（核心实体） ----------
interface ReadingProgress {
  comicId: string;
  chapterId: string;
  chapterIndex: number;
  pageIndex: number;        // 0-based，章内当前页
  pageCount: number;        // 该章总页数（防移动后错位）
  percent: number;          // 0-100，全书维度（跨章累计）
  updatedAt: number;
}

interface Favorite { comicId: string; createdAt: number; }
interface ScanRoot { id: string; path: string; enabled: boolean; lastScanAt?: number; }

// ---------- 设置（服务端持久，前端 localStorage 镜像） ----------
interface Settings {
  readerMode: ReaderMode;
  readDir: ReadDir;
  fitMode: FitMode;
  quality: Quality;
  preloadCount: number;           // 前后预加载页数，默认 3
  pageAnimation: 'none' | 'slide' | 'fade';
  volumeKeyPage: boolean;         // 音量键翻页（移动端）
  keepScreenOn: boolean;          // Wake Lock
  autoScanIntervalHours: number;  // 0 = 仅手动
  thumbnailCacheMB: number;       // 缩略图缓存上限
}
```

### 5.2 SQLite Schema（`app/server-go/internal/db/schema.sql`）

SQLite（WAL，`foreign_keys=ON`），一共 **6 张表**：

| 表 | 一行代表 | 关键列 |
|---|---|---|
| `libraries` | 一个漫画库 | `id` / `name` / `type`(`chapter`\|`single`) / `paths`(JSON) / `sort` |
| `comics` | 一部漫画 | `id`(sha1(path) 前 16 位) / `library_id` / `title` / `raw_title` / `author` / `description` / `format` / `path`(唯一，增量比对键) / `cover_path` / `chapter_count` / `page_count` / `tags`(JSON) / `file_modified_at` / `added_at` / `meta_locked` |
| `reading_progress` | 一部漫画的当前进度 | `comic_id`(主键) / `chapter_id` / `chapter_index` / `page_index` / `page_count` / `percent` / `updated_at` |
| `favorites` | 一次收藏 | `comic_id`(主键) / `created_at` |
| `settings` | 一个配置键 | `key` / `value`（只存 L1：扫描间隔 / 缩略图缓存 / 备注） |
| `sessions` | 一个登录会话 | `token_hash`(SHA-256，DB 被拷走也无法冒用) / `username` / `created_at` / `expires_at` |

**两个容易踩的点**：

- **没有 `chapters` 表**：章节是「按需从源解析」出来的——`scanner.ListChapters()` 现场读目录或
  压缩包中央目录，页数再按需回填（限并发 4）。改章节规则只动 `scanner/`，不需要迁移数据库。
- **没有 `chapter_progress` 表**：分章已读状态整体移除，进度只记「当前在读的那一章」；
  `schema.sql` 里那句 `DROP TABLE IF EXISTS chapter_progress` 只为清理老库。

索引：`comics` 上有 `(added_at DESC, id)` 与 `(library_id, added_at DESC, id)` 两条复合索引——
列表默认 `ORDER BY added_at DESC, id`，次键一起进索引才能整段走索引，否则退化到临时 B-Tree 排序。

## 6. API 契约

响应统一 `{ code: 0, data }` / `{ code: 4xxx, message }`；图片走二进制流，支持 `Range`（206）。

**完整接口清单以 README 的[「API 一览」](../README.md#api-一览)为准**——两处各写一份必然漂移，
本节只记跨接口的约定与资源分组。

| 资源 | 路径前缀 | 说明 |
|---|---|---|
| 漫画 | `/api/comics` | 列表 / 详情 / 元数据编辑 / 封面（上传或从某页提取）/ 单部重扫 / facets |
| 页流 | `/api/comics/{id}/chapters/{ch}/pages` | 页元信息 + 单页图流（`?quality=standard` 走缩略图） |
| 进度 | `/api/progress` | 读写当前进度、重置；列表页用 `?comicIds=` 批量聚合 |
| 收藏 / 记录 | `/api/favorites`、`/api/history` | 收藏增删、阅读记录（`updated_at` 倒序） |
| 漫画库 | `/api/libraries` | CRUD / 排序 / 目录浏览 / 上传 |
| 扫描 | `/api/scan`、`/api/scan/status` | 触发（默认增量）与进度查询 |
| 设置 | `/api/settings` | 只有 L1 三项；偏好按设备存，见 §9.4 |
| 运维 | `/api/health`、`/api/about`、`/api/cache/*`、`/api/backup/*` | 探活、运行信息、缓存治理、数据备份 |
| 登录 | `/api/auth/*` | 单账号门禁：状态 / 登录 / 退出 / 改凭据 / 开关 |

- **桌面**：网格 5–6 列（`minmax(150px,1fr)` auto-fill）；**平板** 3–4 列；**手机** 2–3 列 + 底部 Tab
- **列表视图**：行 = 96px 封面 + 标题/作者 + 底部细进度条
- **状态**：首屏骨架屏（12 卡）→ 内容；空库 → 引导去「设置 → 漫画库管理」；扫描中 → 顶栏下方细 ScanBar（done/total）
- **URL 状态**：`?library=&status=&sort=&view=` 全部进 query，刷新/后退可恢复
- **组件**：`HomePage` → `LibraryHeader` / `ContinueReadingRow` / `FilterChips` / `ComicGrid` → `ComicCard[]` → `CoverImage`（IntersectionObserver 懒加载 + 模糊占位）

### P2 搜索 `/search`

- 布局：移动端全屏（自动聚焦 + 取消按钮）；桌面居中 640px 面板

## 9. 状态管理

### 9.1 三层状态划分

```
服务端状态（TanStack Query，`api/queries.ts`）── 列表/详情/章节/收藏/记录/登录态
   ↕ 失效与乐观更新
URL 状态（query string）── 库/状态/排序/视图/搜索词
组件局部状态（useState）── 阅读器瞬态：控件显隐、抽屉、页码、加载与错误
设备偏好（localStorage，`utils/*Prefs.ts`）── 翻页模式/方向/画质/外观，按设备存
```

前端**不引入全局状态库**：跨页要共享的只有「偏好」（localStorage 读写）和「服务端数据」
（Query 缓存），其余都是单页内的瞬态，放在组件里最省心，也避免出现第二份真源。

### 9.2 Query Keys（`api/queries.ts`）

```ts
export const queryKeys = {
  comics:  (q, pageSize) => [...],   // 列表
  comic:   (id) => [...],
  chapters:(id) => [...],
  // …facets / favorites / records / auth
};
export const LIST_PAGE_SIZE = 36;
```

**要点**：列表 key 的前缀必须保持 `'comics'`——`invalidateQueries({ queryKey: ['comics'] })`
按前缀批量失效，换前缀会让收藏、进度、扫描完成后的刷新全部失灵。

### 9.3 阅读器状态（`components/reader/ReaderShell.tsx`）

阅读器没有全局 store：`chromeVisible`（控件显隐）、`drawerOpen` / `settingsOpen`、
当前页码与章节页数据都由 `ReaderShell` 的 `useState` 承载，随组件卸载一起消失。
需要跨会话留下的只有偏好，读写在 `utils/readerPrefs.ts`。

**要点**：页元信息（可能几百条）不进 localStorage；刷新后页码从 `/api/progress` 恢复。

### 9.4 设备偏好（`utils/devicePrefs.ts` / `readerPrefs.ts`）

- 阅读偏好 + 外观共 10 项，按设备存 localStorage，键统一 `fakenews:` 前缀
- `PUT /api/settings` 只保留服务端需要知道的三项（扫描间隔 / 缩略图缓存 / 备注），其余键静默忽略
- 换设备不共享偏好：同一台 NAS 上手机和平板可以各用各的翻页模式与画质

### 9.5 进度同步 hook（`components/reader/useProgressSync.ts`，阅读器生命线）

```ts
export function useProgressSync(comicId: string) {
  const save = useMutation(api.saveProgress);
  const pending = useRef<ReadingProgress | null>(null);
  const timer = useRef<number>();

  const report = (p: ReadingProgress) => {
    pending.current = p;
    mirrorWrite(comicId, p);                                            // 本地镜像兜底
    clearTimeout(timer.current);
    timer.current = setTimeout(flush, 1000);                            // 防抖 1s
  };

  const flush = () => {                                                 // 立即上报
    clearTimeout(timer.current);
    if (pending.current) { save.mutate(pending.current); pending.current = null; }
  };

  // 切章 / 路由离开 / 页面隐藏 三处强制 flush
  useBeforeUnload(flush);
  usePageHide(flush);          // visibilitychange → hidden（iOS Safari 必需）
  return { report, flush };
}
```

**数据流**：翻页 → `pager.onPageChange` → `report()` → localStorage + 防抖 → `PUT /api/progress` → SQLite。下次进入：详情页"继续阅读"显示 `chapterIndex/pageIndex`；列表页 `readStatus`/`percent` 由聚合接口下发。

### 9.6 阅读器状态机

```
idle ──openChapter──▶ loadingChapter ──pages ok──▶ ready
ready ──gotoPage──▶ reading ──report(debounce)──▶ reading
reading ──switchChapter──▶ flush ──▶ loadingChapter
reading ──error(页缺失/zip损坏)──▶ error ──retry──▶ loadingChapter
任意态 ──exit(返回/隐藏)──▶ flush ──▶ idle
```

## 10. 阅读器实现要点

### 10.1 进度记忆

- **记录时机**：翻页/滚动即记录；**仅打开封面/详情不记录**（「继续阅读」只收录真正翻过页的）
- **恢复**：`/read/:comicId/:chapterId?page=n` —— n 来自 `GET /api/progress`；webtoon 模式恢复 scrollTop（按页高估算 + IntersectionObserver 校正）
- **跨章 percent**：全书维度 = (已读章页数累计 + 章内 pageIndex) / 总页数，服务端计算，前端只展示

### 10.2 章节切换与边界

- 上一章/下一章：底部工具栏按钮 + 章节抽屉；`double/split` 模式下跨章 spread 不拼接（避免错位，翻到章末停留）
- 章末最后一页 → 自动标记 `finished`，弹出"下一章"快捷条
- 文件被移动/删除：`comics.path` 失配 → 扫描清理级联删进度；前端 404 → 阅读器 error 态引导回详情页

### 10.3 图片加载与预加载

- 当前页 ±`preloadCount` 页 `new Image()` 预 decode；webtoon 用 IO 虚拟窗口（视口上下各 3 屏）
- `standard` 画质：320–1280px 宽 WebP 缩略图（按设备 DPR 选择宽度）；`original`：原图流 + Range 渐进显示
- 内存护栏：同时驻留解码图 ≤ 12 张（LRU 淘汰），防平板 OOM

### 10.4 拆分双页（split）

- 进入章节时拉 `pages` 元信息，`width/height > 1.4` 判定为跨页图
- 服务端拆分端点：`GET .../pages/:index?split=left|right` 返回半图，前端按 single 序列化翻页

## 附：与 fn-hello 模板的关系

本工程沿用 fnOS 官方 `fn-hello` 模板的 fpk 外壳（manifest / cmd 生命周期 / wizard / ui 入口模式），
