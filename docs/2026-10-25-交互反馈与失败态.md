# 2026-10-25 交互反馈与失败态（第二批）

上一批解决的是「加载慢 / 看不到内容」，这一批解决**「点了之后发生了什么」**。
共同点：都不是功能缺失，而是「应用知道、但没告诉用户」。

## 起点：audit 出来的 5 处「沉默」

| 位置 | 改之前 | 后果 |
|---|---|---|
| 详情页保存元数据 | 成功只关面板，**失败连提示都没有**（`mutate` 没写 onError） | 用户以为网络卡了，反复点保存 |
| 详情页收藏 | 只有爱心变色；失败是一行马上消失的小字 | 分不清点中没点中 |
| 漫画库新建/编辑 | `saveLibrary` 没有 try/catch | 失败变成未处理 rejection，面板原地不动、一个字不提示 |
| 清缓存 / 立即淘汰 | 没有任何回执 | 不知道释放了多少、有没有真的清 |
| 删除阅读记录 | 点了就消失，**无撤销** | 删的是阅读进度，误触等于「忘了读到哪」 |

另外两处是结构性缺陷：

- **弹层没有键盘支持**：Esc 关不掉、焦点不进面板（Tab 一下跑到背后的页面里）、没有 `role="dialog"`。
- **阅读记录只有 100 条**：接口只有 `limit` 没有 `offset`，读过 100 本以上更早的记录没有入口
  （和上一批的 `pageSize=120` 是同一类问题）。实测夹具 106 条 → 6 条看不见。

## 1. 轻提示（`components/ui/toast.tsx`）

模块级 store + `useSyncExternalStore`，`toast.success/error/info/undo` 可以在任何地方调用
（包括 `onSuccess` 回调与非组件模块），不需要 Context 与 hook。

- 同时最多 3 条，`info/success` 停 2.4s、`error` 4.6s、带撤销的 6s
- 层级 `--layer-toast(140)`：**必须在阅读器(100)/弹层(120)/确认框(130) 之上**，
  否则「在弹层里点保存」看不到结果
- 移动端抬到底部 Tab 之上（`pb-[calc(4.75rem+env(safe-area-inset-bottom))]`），桌面收右下角
- 配色只让图标带语义色，文字走 `ink` 阶：浅色主题下 `red-300` 压在浅底上读不清
- 每条带 `data-toast`，供探针精确命中（页面上还有别的 `role=status`）

接入点：收藏 / 保存元数据 / 重置进度 / 重扫 / 删阅读记录（带撤销）/ 清缓存 / 改缓存上限 /
新建·编辑·删除漫画库 / 触发扫描 / 设置项保存失败。

## 2. 删除阅读记录 → 撤销

`toast.undo()` 给 6 秒窗口，点了就调 `PUT /api/progress` 把原位置写回。两个细节：

1. **必须带回原 `updatedAt`**：按 `now` 写回的话，这条记录会跳到历史列表最前面，
   用户看到「撤销了，但顺序变了」，比不撤销更困惑。为此 `PUT /api/progress` 新增可选
   `updatedAt`（只接受「过去且不超过 now+60s」，防止未来时间把记录钉在首位）。
2. 本地镜像要一起清（`clearLocalMirror`），否则撤销后进阅读器会按镜像定位。

## 3. 弹层键盘 / 读屏（`components/ui/useDialog.ts`）

- Esc 关闭（危险操作进行中不响应，避免「按一下 Esc 好像取消了」的错觉）
- 打开时焦点移入面板、关闭后**还给原来的元素**（`preventScroll`，不把页面拽回去）
- Tab 在面板内循环
- `role="dialog" aria-modal="true" aria-label`
- 确认框的初始焦点给**取消**而不是确认：危险操作不该被一个回车直接执行

踩到的坑：Sheet / ConfirmDialog 都是「`open` 变 true 后组件才挂载」的两段式渲染，
hook 的 effect 跑的时候 `ref.current` 还是 null，一次性 `focus()` 静默失败
（实测焦点停在背后的导航上）。改成**几帧内重试**才稳。

## 4. 阅读记录分页

- 后端：`GET /api/history?limit=&offset=` 返回 `{items, total}`（`total` 是 `reading_progress` 总行数）
- 前端：书架改用 `useHistoryFeed`（`useInfiniteQuery`，每页 30），滚到底续拉；
  标题显示「阅读记录 (106 · 已显示 30)」
- `queryKeys.history()` 仍是前缀，既有的 `invalidateQueries({ queryKey: ['history'] })` 全部照旧生效

## 5. 阅读器失败态

**单页图加载失败**（`PageImage` 之前完全没有 `onError`）：压缩包里某张图损坏 / 服务端 415 时，
`<img>` 永远停在 `opacity:0`，用户看到一整屏纯黑，分不清「这页是黑的」「还在加载」「应用卡死」。
现在四种翻页模式都给说明 + 「重新加载」：

- 重试靠 `?retry=N` 绕开 HTTP 缓存（同一个 URL 可能连失败响应一起被缓存）
- 按钮上 `stopPropagation`：阅读器的「点击切工具栏」「拖动翻页」都监听在外层容器，
  不拦的话点一下重试会顺带翻页
- 卷轴模式额外保留 `onError` 撑高度（否则该页高度为 0，续读定位与滚动几何全坏）

**详情请求失败**：以前和「漫画不存在」共用一句「可能已被移动、删除」——断网时等于误报删库。
现在显示真实原因 + 「重试」。

## 刻意没做

- **所有提示都做成 toast**：设置页开关这类乐观更新、且界面上本来就有明确状态变化的操作，
  成功时保持安静（只在失败时提示）；每条都弹会变成噪音。
- **弹层打开时锁 body 滚动**：需要补 `padding-right` 抵消滚动条宽度，否则桌面端会横向抖一下；
  收益（背景不跟着滚）不抵这个风险，先留着。
- **阅读记录乐观删除**：删除后靠 invalidate 重取（4 页 ~几十 KB）。做乐观更新要处理
  「撤销 + 并发 refetch」的竞态，收益不明显。
